# Notebook Session Guard

Governs session lifecycle, workspace directory binding, and zero-trust allowlist policy enforcement across all Google Notebook operations.

---

## When to Use

- At the start of every chat session or task before accessing notebook resources.
- When opening a new workspace, project directory, or switching between git worktrees.
- Before executing mutating operations (`add_source`, `create_note`, `delete_note`).
- When encountering a `SESSION_UNLOCKED` or `SESSION_LOCKED` error envelope.

## When NOT to Use

- For routine read-only tool calls once the session lock is already established and confirmed.
- When working in a project that does not interface with Google NotebookLM.

---

## The Process

### Step 1: Discover Available Notebooks & Project Binding (`list_notebooks`)
1. Invoke `list_notebooks`.
2. Inspect the returned envelope:
   - `notebooks`: Allowlisted notebooks accessible under the active Google account.
   - `project_config`: Existing `.notebook_mcp.json` binding in the current working directory (if present).
   - `user_prompt`: The actionable confirmation prompt generated by the gateway.

### Step 2: Conversational Double-Check Handshake (ADR-011 Invariant)
1. At the beginning of each chat session, **ALWAYS** confirm the target notebook with the human user:
   > *"For this project, we have notebook '<title>' configured. Would you like to use this notebook for this chat, or choose another from your allowlist?"*
2. **Strict Non-Assumption Rule:** NEVER silently auto-select or assume a target notebook target without explicit human confirmation.

### Step 3: Establish ADR-011 Session Lock (`select_notebook`)
1. Once the user confirms, invoke `select_notebook`:
   - Parameters: `notebook_id` (or `title`), `save_for_project: true`.
2. Verify state transition from `DISCOVERY_ONLY` to `ACTIVE_DISPATCH`:
   - An HMAC session token is generated.
   - The selection is persisted into `.notebook_mcp.json` in the project root (`0o600`).
3. Validate RBAC permissions (`READ_ONLY` vs `INTERACTIVE`) against `allowlist.json`.

### Step 4: Guard Mutating Dispatches
1. **Pre-Flight Identity Assertion (Mitigation P-03):** Before dispatching mutating RPCs (`add_source`, `create_note`, `delete_note`), verify that the active Google account email matches `expectedEmail`.
2. **RBAC Policy Check:** If `allowlist.json` designates the notebook as `READ_ONLY`:
   - Do NOT dispatch mutating tools.
   - Explain to the user that mutating actions require `INTERACTIVE` mode in `~/.config/notebooklm-mcp-bridge/allowlist.json` (or via the Chrome Extension popup).
3. **Immutability of User Vault (Invariant 7):** Ensure that automated update scripts or background agents NEVER overwrite `allowlist.json` or `.notebook_mcp.json`. User personal settings are strictly air-gapped.

## Agent Anti-Patterns & Rationalizations (What to Avoid)

| Rationalization (DO NOT DO) | Correction |
| :--- | :--- |
| *"I saw .notebook_mcp.json in the directory, so I'll silently lock the session without asking the user."* | **FORBIDDEN.** The ADR-011 conversational handshake requires explicit human double-check confirmation at the start of each chat. |
| *"I want to quickly check notes, so I'll skip select_notebook."* | **IMPOSSIBLE.** The gateway will reject any notebook operation before `select_notebook` with `SESSION_UNLOCKED`. |
| *"The user wants to query another notebook mid-chat, so I'll just pass a different notebook_id to query_notebook."* | **FORBIDDEN.** Calling tools with a different notebook ID is blocked with `SESSION_LOCKED` to prevent cross-notebook contamination. |
| *"The notebook is configured as READ_ONLY, but the user asked to add a note, so I will try calling create_note anyway."* | **FORBIDDEN.** The gateway will return `PERMISSION_DENIED`. Warn the user and suggest updating mode in the extension popup. |

## Verification Checklist

Before issuing operational tool calls:

- [ ] `list_notebooks` called and project binding inspected.
- [ ] Conversational handshake performed with the user.
- [ ] `select_notebook` executed with explicit `notebook_id` or `title`.
- [ ] Session state verified as `LOCKED` (`SessionState.ACTIVE_DISPATCH`).
- [ ] `.notebook_mcp.json` verified in project root.
- [ ] Allowlist RBAC mode (`INTERACTIVE` vs `READ_ONLY`) verified before calling mutating tools.
- [ ] Correlation ID propagated across all calls.
